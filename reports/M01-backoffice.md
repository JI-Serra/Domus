## What was built

- **Barrios (F01/F02/D20)** `/platform/tenants`: searchable list with subscription badges (icon + text); `/new` create form (Zod from `@domus/domain/platform`, slug suggested from the name, logo uploaded to the private `tenant-logo` bucket under `<tenant_id>/`, idempotent through a per-form `client_event_id`); `/[tenantId]` detail: data + logo edit, subscription change through a native-`<dialog>` confirmation that states the effect (suspended = solo lectura, baja = sin acceso), billable criteria with "conteo disponible en H2" behind an InfoButton, first-admin invitation form (`send-invitation`, retry-safe key kept after a failed delivery, renewed after success) and the invitation list with status and revoke.
- **Invitation acceptance** `/invitations/accept?token=…` (public route): the email link ends here with the session in the URL fragment; a small client gate hands it to a Server Action (`setSession`) and the redirect drops the fragment. Signed in → barrio + role confirmation, optional password, `accept_invitation`, context cookie set to the new membership, lands in the barrio. Signed out → sign-in with the invitation preserved. Expired link, used link, wrong account, forged and malformed tokens all render the **same** page (asserted equal in e2e).
- **Soporte / impersonation (F04, D18)**: `/platform/support` (barrio → person lookup, required reason, duration default 30 / max 60, history, ending an active session started elsewhere). The `support-session` token is requested by a Server Action and kept only in the **httpOnly, SameSite=Lax cookie `domus-support`** (expires with the session). `createRequestClient()` returns the support client (`@domus/supabase/platform`) while it is live, `proxy.ts` and `getRequestContext()` resolve the context as the target, so the whole app renders as that user; the admin's own cookies are never touched. The token never appears in HTML, props or client JS (e2e asserts it). "Terminar", auto-exit at zero (client countdown) and cookie/token expiry all end the session and return to `/platform/support`; the proxy also clears a dead token. Banner: inverted high-contrast bar inside the sticky header, wraps on 360 px, countdown `mm:ss`. Blocked while impersonating: `/account`, `/invitations`, `/auth`, sign-in/recovery, `/design`, `/platform` → a "No disponible durante el soporte" page; security link and sign-out are removed from the top bar; `client.auth` on the support client throws (fail-closed for any code that forgets).
- **`/settings` + `/settings/support`**: tenant admins with `access_audit` see every support access (Equipo de Domus, as whom when readable, when, reason, duration, status); admins without the permission are told what is missing; other roles get 404.
- **Cancelled barrio**: users whose only memberships are cancelled see "Tu barrio fue dado de baja" with the barrio name(s) and logout; users with no barrio at all still see the generic page (both asserted).
- UI primitives added: `ConfirmDialog`, `Textarea`, `PageHeader` action slot, `useSubmitAction` (keeps typed values after a failed submit — React 19 resets forms after an action, which desynchronized controlled selects; found by the e2e).

## Decisions and things to know

- **Platform names of targets**: a platform admin cannot read people (S5), so the session history identifies the supported user by a short code; the barrio's administrators see the name when they hold `registry`.
- **Writes during support**: no tenant write UI exists yet, so the e2e makes a write with the same support token the server uses (cookie read by Playwright) and checks in `audit_event` that the actor is the platform admin, `on_behalf_of` the target, with the session id; it also proves the token cannot change the password through the Auth API and that the ended session reads nothing.
- Logo blobs: the e2e removes objects through the Storage API; direct SQL deletes are blocked by Storage.
- Edge functions must be served for the e2e: `pnpm supabase functions serve --env-file supabase/.env.local` (created by `node supabase/functions/local-demo.mjs --prepare`, gitignored; `DOMUS_APP_URL=http://127.0.0.1:3000`).
- Existing `tenant-status.spec` cancelled-barrio test now asserts the new page. `database.types.ts` is Prettier-ignored but committed formatted: regenerate with `pnpm gen:types` then `prettier --ignore-path <empty> --write`.
- No new dependencies. No `service_role` anywhere in the web app.
