## Decisions and things to know

- **Permissions in the UI are display only.** `AdminPermissionsProvider` (fed by `membership_permission` through the user's own RLS client) filters navigation; every page calls `requireAdminScope(...)` (404 for strangers) and every Server Action starts with `writableScope(...)` (`denied` / `readOnly`). The database remains the control.
- **Guards page needs `registry`, not `guards`.** The DB only lets `registry` administrators invite non-admin roles, read `membership`/`person` and revoke memberships; `guards` alone cannot read the guard list. So _Guardias_ is gated on `registry` (assigning gates additionally needs `guards`; without it the assignments are read-only text) and _Puestos_ on `guards`. A guards-only administrator therefore sees Puestos but not Guardias. If the product wants guards-only administrators to manage guards, the DB needs a guard-list RPC (not done: DB is out of scope).
- **One-time link needs a fresh mailbox proof.** Acceptance requires the session to have proven the email _after_ the invitation was created (`session_proves_email_since`). A person who opens the link signed out and signs in with an email link accepts; someone already signed in by password gets "invitación no disponible" until they sign in by email link. The link's InfoButton says so. (Found by the e2e.)
- **Device credential.** `redeem_device_pairing` returns the 256-bit token once. The tablet page keeps it in an **httpOnly, SameSite=Strict `domus-device` cookie** (server code only; never in props, HTML or client JS; e2e asserts `document.cookie` does not contain it and that the credential syncs, then fails after revocation) as groundwork for M13. Pairing codes are the DB's 32 hex characters, shown as 8 groups of 4.
- **Import safety.** `papaparse` 5.7.0 (CSV) and `read-excel-file` 9.3.10 (XLSX read; returns stored cell values and never evaluates formulas or macros), `write-excel-file` 4.1.1 (template). All loaded lazily when used. Files > 5 MB, > 8,000 rows, unknown / duplicate / missing columns are rejected before anything is sent. XLSX is a zip: a hostile file can only exhaust the administrator's own browser (accepted; the 5 MB cap bounds the input). Imported text is only ever rendered as text; the template contains no user data, so no formula neutralization was needed on export. Server Actions accept up to 8 MB (`serverActions.bodySizeLimit`) so 8,000 rows fit.
- **Errors are words.** Domain schemas return message keys / codes; `registryErrorKey` maps SQLSTATE (`42501`, `22023`, `23514` holder rule, `23505` unit code / plate / person, deadlocks as `busy`) to `registry.errors.*`; raw database text never reaches the browser and unexpected failures go through `reportError` with the code only. The e2e hit a real deadlock (`40P01`) while other workers wrote to the shared stack, hence the retryable "busy" message.
- **Approvals (T19).** `decide_unit_join_request` can now answer `identity_conflict` (nothing created, request stays pending): shown with an explanatory message.
- **Shared components** added under `components/ui`: `copy-text-button`, `one-time-secret`, `countdown`, `pagination`, `sub-nav`. `file-picker.tsx`, `sheet.tsx` and the `value?` field of `PlatformFormState` were **copied verbatim from the sibling resident-UI worktree (`h2-t16`)** so the two branches add identical files; if that worker changes them first, take theirs.
- Page header actions now wrap on small screens (`PageHeader`: `shrink-0` → `max-w-full`); the e2e found 74 px of horizontal overflow on the unit sheet at 360 px.
- Texts live in `messages/registry.es-AR.json` (merged in `i18n/request.ts`, typed in `next-intl.d.ts`), keeping the shared `es-AR.json` almost untouched (nav labels + file picker strings only) to avoid merge noise with the other worker.
