# M00-F02 + M00-F03 + M00-F08: design tokens, /design page, app shell, i18n base

Implemented typed design tokens with a generated Tailwind v4 theme, the UI primitives, an internal `/design` page, the app shell with an always-visible switchable context selector, `next-intl` with es-AR as the only locale, and domain formatters for ARS amounts and tenant-time-zone dates. Theme handling covers system/light/dark plus "modo garita", persisted per browser.

### Tokens: single source and drift check

`packages/ui-tokens` holds typed values (colors for `light`, `dark`, `gate-light`, `gate-dark`; the product and gate type scales; spacing, radius, touch, layout, shadow, motion). Plain TS with no DOM or Tailwind dependency, so React Native can import it. `generateTokensCss()` produces `tokens.generated.css`; `pnpm gen:tokens` writes it. A test in `apps/web` fails if the committed file differs from the generator. A contrast test in `ui-tokens` asserts WCAG AA for every text pair in regular themes and AAA (7:1) in the gate themes.

Theme attributes on `<html>`: `data-theme="light|dark"` (absent means follow `prefers-color-scheme`) and `data-mode="gate"`. An inline script restores them before first paint. Gate mode also raises the type scale and `--control-height` (44 → 56 px).

### Shell and context

`ActiveContext` (`membership_id`, `tenant_id`, `tenant_name`, `tenant_time_zone`, `membership_role`, `unit_id`, `unit_name`) and `ActiveContextProvider` (`contexts`, `initialMembershipId`, `onSwitch`) are the swap point. `MockActiveContextProvider` in `app/(app)/layout.tsx` feeds four fictional memberships. For auth, replace that one component with a provider built from real `membership` rows; consumers use `useActiveContext()`. Navigation per role is placeholder: each destination renders an empty state ("Esta sección llega pronto") through `app/(app)/[section]`, restricted to known slugs.

## Deviations from DESIGN.md (and why)

1. **`--color-success` light: `#1a7f37` → `#187a35`.** The specified value is 4.47:1 on `--color-success-bg` (AA needs 4.5). Dark values are as specified.
2. **New `--color-on-accent`** (white in light, black in dark). White on dark `#0a84ff` is 3.65:1, which fails AA for 17 px button text. The accent itself is unchanged.
3. **New `--color-text-placeholder`** (`#5f5f5f` light). `--color-text-secondary` `#707070` on `--surface-2` (inputs) is 4.06:1. Secondary text is only used on `surface-0/1`.
4. **New dark `--color-ember` `#ff9a63`.** The Part B `#b64400` is 3.09:1 on `surface-1` in dark. No dark value was specified.
5. **Gate-mode palettes** are new: Part A requires 7:1 but gives no values.
6. **Token names.** Part A's `--surface-0`, `--text-primary`, `--accent`, `--hairline` are emitted as `--color-surface-0`, `--color-text-primary`, … so Tailwind generates utilities. Spacing keeps Tailwind's 4 px multiplier (`--spacing: 4px`), so Part B's scale values are `p-1…p-36`, not `--spacing-N`.
7. **Part B marketing scale and finish swatches are not emitted** (landing only). Ember and Part B's ink/gray/hairline/canvas values are covered by the semantic tokens.
8. **Dropdowns (context selector, appearance menu)** use a 1 px hairline border and no shadow, since the only allowed shadow is the modal one. Not specified in Part A.
9. **Destructive button "pide confirmación"**: the button is styled per spec; the confirmation dialog is out of scope for this task.
10. **Traffic-light panel**: shown compact (`fill={false}`) on `/design`; in use it fills at least 50 dvh. The result font size is capped at `11.5vw` so 56 px gate text does not overflow 360 px screens.

## Decisions and caveats for the coordinator

- **`next-intl/plugin` is not used.** It imports `@swc/core` eagerly, and `@swc/core` 1.16.13 refuses to load on this machine because `%LOCALAPPDATA%` grants write access to the Codex sandbox account (`CodexSandboxUsers`). That failed `next typegen`, `dev` and `build`. `next.config.ts` declares the `next-intl/config` alias directly (Turbopack and webpack), which is all the plugin does without its extractor. Switch back to `createNextIntlPlugin()` if the extractor is ever adopted. While testing the workaround I created empty directories `C:\swc-cache`, `C:\Users\Public\swc-cache` and `C:\ProgramData\swc-cache`; the cleanup was blocked by the safety check, so they are safe to delete.
- **`pnpm-workspace.yaml`** now has `@parcel/watcher: false` and `@swc/core: false` under `allowBuilds`; `pnpm install` fails with ERR_PNPM_IGNORED_BUILDS without a decision (next-intl dependencies).
- **`lucide-react` is pinned to 1.52.0**, not the 1.54.0 latest: the registry release-age gate blocked 1.54.0 (published the same day).
- **`.prettierignore`** lists the generated CSS so the sync test is not broken by formatting.
- **Tooling quirks**: `turbo` and `next dev` each append or generate an `AGENTS.md` block/file ("agent rules"). I did not commit those changes (reverted `AGENTS.md`, deleted `apps/web/AGENTS.md`). Setting `"agentGuidance": false` in `turbo.json` would stop the first.
- **Node 25 `localStorage`**: the experimental global shadows jsdom's, so `apps/web/src/test/setup.ts` installs an in-memory Storage.
- **Formatting**: `formatCurrencyArs` uses a no-break space (U+00A0) after `$` (`$ 1.234,56`), as ICU does for es-AR. `formatDate` leaves date-only strings (`2026-10-09`) unshifted by the time zone.
- **`ui-tokens` imports use `.ts` extensions** so Node can run the generator script natively; `allowImportingTsExtensions` is enabled in `ui-tokens` and `web` tsconfigs.
- **Hard-coded text** is blocked by ESLint (`react/jsx-no-literals` on non-test TSX).
- **Home route** moved to `app/(app)/page.tsx` (the T1 smoke test moved and was updated).
