## Contract and decisions

- `submit_unit_join_request(join_code text, person_data jsonb, client_event_id uuid, target_tenant_id uuid default null)` is the single public signature. PostgreSQL requires defaulted arguments after required arguments, so the optional tenant is last. Named PostgREST arguments stay compatible; old positional SQL callers now use named notation. Tenant is resolved by the globally unique join-code hash; supplied tenant mismatch returns the unchanged uniform `{status:"unavailable"}`. Existing verified identity, support exclusion, payload rules, per-user all-attempt throttling, failed-only tenant counters and deduplication remain intact. Unknown tenantless failures use the existing `join:tenant:none` counter scope.
- `my_unit_join_requests()` returns exactly five fields: `unit_join_request_id`, `unit_join_request_status`, `unit_join_request_created_at`, `tenant_name`, `unit_code`. Only the live ordinary caller's requests are selected; no membership is required and no tenant browsing is granted. Support identities are denied. Suspended tenant requests remain readable; cancelled tenants are hidden. Ordering is newest first with UUID as tie-breaker.
- `cancel_unit_join_request(target_unit_join_request_id uuid, client_event_id uuid)` returns `{status:"cancelled"}`. An ordinary caller can cancel only an owned pending request in a pilot/active tenant. It locks only an owned request, then uses the existing actor/tenant/operation/payload-bound receipt mechanism. Same-event retries return the receipt without a second write/audit; new events for terminal requests or mismatched event reuse are denied. Missing/foreign/nonpending/blocked-tenant/support/invalid identities use SQLSTATE `42501` and `Join request management denied`. Cancellation records the requester as decision author and records its timestamp; audit PII redactions remain unchanged.
- `unit_sheet(target_tenant_id, target_unit_id)` always includes `member_permissions: Record<membership_id, household_permission[]>`. Active eligible holders or registry administrators see explicit grants for household memberships belonging to that unit, including `[]` for memberships with no grants. Other callers get `{}`. Support consumes the target's unit/registry rights in its bound tenant and still gets no pending onboarding arrays. Holder implicit full capabilities remain represented by the existing `permissions` field.
- Added `cancelled` to `unit_join_request_status` and the glossary. Enum addition is committed in its own migration before use. Complete SQL definitions retain empty `search_path`, the central identity validator and explicit authenticated-only ACLs under the isolated registry writer. No catalog-body rewriting is used.
- The first local apply required creating the replacement unit sheet while explicitly assuming its owner, `registry_writer`. The applied cancellation definition initially attempted a tenant share lock, which needs tenant UPDATE permission; migration 11 replaces the full function with request-only locking while preserving the isolated writer's existing privileges. Applied migrations were kept immutable.
- Regenerated Supabase types; added `myUnitJoinRequests`, `cancelUnitJoinRequest`, and the permission-map type to the typed wrappers. No domain schema or UI change was needed.
